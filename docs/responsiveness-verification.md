# 速度と操作の改善

2026-10-14、Windows / Emacs 31.1、neo-scope 0.4.0。
ユーザー設定全体は起動せず、対象設定を読み取り、実際の `emacs.d` の6,416ファイルと導入済みOrderless・Consult・Vertico・Evilを隔離 `-Q` 環境で使用した。

`tests/neo-scope-performance.el` による同一ファイル集合の単回計測:

| 処理 | 改善前 | 改善後 |
| --- | ---: | ---: |
| ファイル列挙 | 7.030秒 | 0.363秒 |
| Orderless `init` | 0.071秒 | 0.031秒 |
| Orderless `neo` | 0.073秒 | 0.049秒 |
| Orderless `config ui` | 0.059秒 | 0.014秒 |
| 同一コードのプレビュー10回 | 0.395秒 | 0.064秒 |

ファイル列挙は任意のrgによる非同期取得。候補数・除外・隠しファイル・日本語パスがElisp列挙と一致するテストを追加した。Orderlessは候補ごとのコンパイルをバッチ単位にし、元の照合結果・強調・同名候補を維持する。照合バッチの固定待ち時間は10msから1msへ短縮した。表の照合時間は待ち時間を除いた計算時間で、GUI全体の体感速度とは区別する。

テキストプレビューは変更検出付きで16件まで色付き内容を保持する。ファイルアクセス時刻による不要な無効化を避け、更新・属性変更時刻とサイズ、編集中バッファの変更tickを使用する。初めて開く別ファイルの同期読込・色付けは残る。

GUI検証ではEvil有効状態から直接 `beta` を入力し、結果の確定・元の分割・元バッファのEvil有効状態の復元、ペイン終了を確認。Verticoは非同期列挙とひとつのミニバッファでのConsult正規表現検索・RET確定・C-g取消を確認した。

全48件のERT、バイトコンパイル、通常GUI、任意連携GUIを検証。新規の回帰テストは色付きプレビューの再利用・編集後の無効化、Orderlessバッチ結果、rgとElispの候補集合、入力直後のRETによる最新候補の確定を含む。

rg未導入時のElisp列挙と初回プレビューには同期I/Oの待ち時間が残る。実設定全体を読み込んだ手動IME入力、他OS、大規模・低速ドライブは未検証。処理や機能を削除して速度を上げる変更は行っていない。

## 追加最適化

同じ6,416件を対象に、前段の0.4.0実装と追加変更後をそれぞれ3回計測した中央値。基準ソースは隔離導入時のスナップショットを `build/optimization-reference.el` に保存し、両方をソース読み込みで実行した。

| 処理 | 前段の改善版 | 追加変更後 |
| --- | ---: | ---: |
| 空入力・自作ファジー | 69ms | 42ms |
| 自作ファジー `init` | 103ms | 75ms |
| 自作ファジー `neo` | 96ms | 69ms |
| 自作ファジー `config ui` | 99ms | 66ms |
| 空入力・Orderless | 210ms | 30ms |
| `n`から`neo-scope`まで9段階の照合 | 937ms | 426ms |

9段階の最終結果はどちらも147件。表は照合・描画処理の計算時間で、デバウンス・タイマー待ち・物理キー操作・実設定全体の遅延は含まない。

文字探索を組み込みstring-searchに交換し、検索文字列をバッチ単位で準備する。空入力では照合不要な標準設定の全件表示を直接生成する。Orderlessのカスタムseparatorが空入力でも条件を生成する場合やface付き照合文字列は通常処理を維持する。

自作ファジーマッチに限り、列挙と前の照合が完了している状態で検索語を末尾に追加した場合は前の結果を再照合する。取得順を保持し、同点の順位が変わらないようにする。削除・matcher変更・列挙途中では全候補を再照合する。画面上の候補が変わらないstatus更新では本文を再描画せず、ヘッダーだけ更新する。
