# Embark引き継ぎと全文検索の検証

2026-10-29、Windows / Emacs 31.1で実施。変更はneo-scope内だけ。ユーザーのinit、導入済みパッケージ、兄弟リポジトリは変更していない。

## 実装

- `neo-scope-embark.el` の任意連携を追加。`C-. A N` で取得済み候補一覧を渡し、空の入力欄から追加の絞り込みを行う。
- 候補の順序、同名候補、未保存バッファのマーカー、grepのファイル・行・一致列を保持する。
- Embarkが操作後に選択ウィンドウを復元するため、neo-scopeを開く処理はその後のタイマーで行う。専用GUIで発見した入力フォーカスの問題を修正した。
- 標準全文検索は同じEmacs内で実行する。行走査の途中でも8msまたはバッチ件数を目安に処理を分け、照合位置一覧の二重計算を省く。別プロセス・スレッドは追加しない。

## 自動検証

- ERT 67件成功。従来のファイル・grep・プレビュー・メディア・応答性・Consult/Orderless/Vertico連携のテストを含む。
- Embarkテストでは実際の `embark-act-all` とCollectの候補取得を使用。順序、同名、編集後のマーカー位置、grep一致列、対応外混在、空・リモート・無効候補、登録の再実行と既存キー保持を確認。
- grepテストでは1ファイル内での分割・途中取消・開始前取消・空検索・結果上限・除外・UTF-8/UTF-16・設定されたShift JISの復号を確認。検索中の `make-process` 呼び出しを禁止しても成功。
- `neo-scope.el` と `neo-scope-embark.el` を警告をエラーとしてバイトコンパイル。生成先は `build/embark-grep/`。
- 独立レビューで実際のConsult混在候補がバッファオブジェクトを保持するケースを発見。`consult--buffer-pair` / `consult--multi-format` / Embarkの変換を使うテストで失敗を再現し、修正後に全67件・GUIを再実行した。

## 実パッケージとGUI

導入済みのEmbark 20260610.302、embark-consult 20260503.118、Consult 20261004.957、Vertico 20260913.1525を読み取り専用で使用。

`tests/neo-scope-embark-gui.el` を `-Q` の専用GUI Emacsで実行し、15項目成功。

- 実際の `consult-line` → `C-. A N` で絞り込んだ2件だけを引き継ぐ。
- ミニバッファ終了、空の入力欄、入力フォーカス、追加入力で1件に絞る操作、未保存内容のプレビュー。
- `RET` で正しいバッファ・行へ移動。再度の引き継ぎと `C-g` で元のウィンドウ分割・位置を復元。
- 実際の `consult-ripgrep` → `C-. A N` で2件を引き継ぎ、追加絞り込みと `RET` で日本語名のファイルの正しい行・一致列へ移動。

GUI操作はキー列による自動検証。ユーザーの常用Emacsでの手入力や視覚的な確認とは区別する。

## 検索性能

変更前のHEAD版と変更後のソースを同じEmacs内で交互に読み込み、同一コーパスを各5回検索した中央値。通常の設定値を維持し、ログが結果へ混ざらないよう `build` だけ除外した。実repoの変更時点の内容に対する比較で、下の記録文書自体を追加する前に測定。

「最大待ち」は1msのイベント処理待ちループが戻るまでの最長間隔。画面描画・物理キー入力の遅延ではない。結果の全候補データのハッシュは全試行で変更前後一致した。

| 対象・検索語 | 件数 | 最初の結果 ms（前 → 後） | 完了 ms（前 → 後） | 最大待ち ms（前 → 後） |
| --- | ---: | ---: | ---: | ---: |
| 実repo: `neo-scope` | 1,186 | 9.50 → 8.46 | 157.59 → 85.61 | 26.97 → 13.20 |
| 実repo: `candidate source` | 10 | 8.88 → 8.60 | 48.59 → 20.70 | 14.28 → 9.12 |
| 実repo: `日本` | 33 | 8.57 → 8.54 | 57.06 → 20.18 | 14.91 → 9.17 |
| 高密度fixture: 1ファイル8,000行、`beta alpha` | 8,000 | 411.74 → 8.37 | 411.80 → 460.62 | 411.75 → 18.89 |

高密度fixtureでは操作へ制御を返す回数が増えるため、完了までの時間は約12%増えた。一度に約412ms止まっていた走査を約19ms以下の待ちへ分割できたことを確認した。実repoでは完了までの時間も短縮した。

再測定用関数は `tests/neo-scope-grep-benchmark.el`。この実行の比較用runner・元ソース・ログは `build/embark-grep/compare.el`、`baseline.el`、`comparison-final.log` に保存した。

## 限界

- 同期ファイル読取・ディレクトリ列挙、GC、単一行の処理時間はタイマーの8ms目安を超えうる。遅いドライブでの停止を完全には除去しない。
- Consult候補の位置情報は既存のConsult/embark-consultの形式に依存する。Emacs 29.1/30.xおよび他のパッケージ版での実行は未確認。
- 標準の検索機能を変更したもので、既存の任意Consult/rgソースやメディア用の外部処理の構成は変えていない。
