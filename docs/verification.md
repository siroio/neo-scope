- バイトコンパイル: エラー・警告なし。
- GUI: 独立したEmacsプロセスで子フレーム、3ペイン、入力による絞り込み、候補確定、元のバッファ・point・window-start・選択ウィンドウへの復帰、再表示、プレビューからの中止、子フレーム削除、親リサイズ、親削除とリソース回収を自動確認。終了コード0。

- 別エージェントによるレビュー: 全ペインの操作キーとgrep一致強調の2件を修正し、失敗を確認した回帰テストが成功。

GUIテストはElispで入力バッファやキーの束縛を操作したもの。実キーボードでの日本語IME変換やマウス操作の体感は未検証。GitHubへのpushは行っておらず、GitHubから実際にダウンロードする検証は未実施。Emacs 29.1/30および他OSでの実機検証も未実施。

## ローカル測定

隣接する実際の `emacs.d` を標準ファイルソースで列挙した。6,416ファイル。除外は既定値、キャッシュ状態は制御していない。

| 対象 | 結果 |
| --- | --- |
| 全件列挙 | 6.477秒（先行測定7.258秒） |
| `init`の全候補照合 | 10回合計0.460617秒、平均46.1ms |
| `neo`の全候補照合 | 10回合計0.386745秒、平均38.7ms |
| 日本語クエリの全候補照合 | 10回合計0.450118秒、平均45.0ms |
| 測定用EmacsプロセスのWorking Set | 100ms間隔で観測した最大50.9MiB |

照合測定は描画・ソート・入力待ち時間を含まない。メモリ値はEmacs全体であり、neo-scopeだけの増分ではない。GUI応答時間や大規模リポジトリ一般の性能を保証する数値ではない。

初回列挙には改善余地がある。タイマー単位の処理量・時間を制限して逐次表示するが、単一のディレクトリ列挙・ファイル読込は同期I/Oである。現段階では高速性より、依存なしの本体と中止可能な処理を成立させた。
