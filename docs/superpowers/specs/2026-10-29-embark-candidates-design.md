# Embarkの候補をneo-scopeへ引き継ぐ

## 目的

Consult等で絞り込んだ候補一覧をneo-scopeへ引き継ぎ、プレビューと追加の絞り込みを行う。候補一覧を引き継ぐ方式はユーザー選択済み。元の検索を再実行する方式は今回の対象にしない。

## 操作

1. `consult-ripgrep`、`consult-line`、ファイル・バッファ選択などで候補を絞る。
2. Embarkの一括操作から「neo-scopeで開く」を選ぶ。設定例のキーは `C-. A N` とする。`A` は候補全体への操作で、選択済み候補があればその集合を使う。
3. ミニバッファを閉じ、候補一覧とプレビューをneo-scopeに表示する。
4. 空の入力欄で、その候補集合をさらに絞る。元のConsult検索語は再解釈せず、検索条件として適用済みの結果を扱う。
5. `RET` で対象を開く。`C-g` / `Esc` でneo-scopeを閉じ、起動前の編集画面に戻る。

受け渡すのは切り替え時点で取得済みの候補。切り替え後に元の非同期検索の結果を追加しない。候補の順序と同名候補の区別を保持する。元の検索を続ける操作や逆方向の切り替えは追加しない。

## 対応範囲

- ローカルファイルと生存しているバッファ。
- `consult-line` などの位置付き候補。行・移動先を保持し、未保存バッファも参照できるようにする。
- `consult-ripgrep` / `consult-grep` / `consult-git-grep` のファイル・行付き候補。
- `consult-buffer` のファイルとバッファが混在する候補。
- Embark Collectに集めた上記候補。

空の一覧、対応外の候補種別、リモート対象、消えた対象は理由を表示する。対応外の候補を黙って除去しない。ブックマーク・コマンド・変数など任意のEmbark対象すべてへの対応は今回の範囲に含めない。

## 方式の比較

- **候補の一括引き継ぎを採用する。** ユーザーが選んだ方式。Embarkの `embark-multitarget-actions` とアクションフックを使い、候補一覧を既存のneo-scope sourceへ変換する。neo-scopeの画面・絞り込み・プレビューを再利用する。
- `embark-export` の標準出力先をneo-scopeへ置換する案は採用しない。既存のDired・Occur・Grepへの書き出しも利用できる状態を保つ。
- `embark-become` で検索コマンドを切り替える案は採用しない。今回選択された候補集合の引き継ぎとは動作が異なる。

`C-. A N` は実装側の提案。現在のEmbarkで `A` が候補一括操作、対象の通常アクションマップで `N` が空いていることを確認済み。既存の `C-. N` では単一候補への操作になるため、一覧の引き継ぎとして案内しない。

## 変更範囲と依存

`neo-scope/` 内の任意Embark連携、README、関連テストを対象とする。基本機能にEmbark・Consultを必須依存として追加しない。導入済みのEmbark・Consultは読み取り専用で連携確認に使う。

既存sourceの `:start` / `:preview` / `:action` を利用し、必要な候補の位置情報を保持する。Consult内部APIが必要な箇所は連携部分へ限定し、取得不能な位置を推測しない。

キーの設定例をREADMEに記載する。`emacs.d/init.el` や実環境への有効化、インストール、commit・pushはこの変更に含めない。

## 検証

- 候補の順序、同名候補、パスと行、未保存バッファの位置、空一覧、対応外の候補を確認する。
- 実際のEmbarkの一括操作から、選択中の1件ではなく絞り込んだ候補集合が一度だけ渡されることを確認する。
- 専用EmacsでConsult検索からの切り替え、追加の絞り込み、プレビュー、確定、取消後の画面復元を確認する。
- Embarkの標準collect/export、既存neo-scopeの検索・任意連携の回帰を確認する。
- バイトコンパイルを確認する。生成物と一時データはneo-scope内へ隔離し、実台帳やユーザーinitは使用しない。

## 全文検索の応答性

ユーザーの「別プロセスにしないでください」に従い、標準の全文検索は同じEmacs内で処理する。ファイル間だけでなく一致行の走査中にもタイマーで処理を分割し、検索に不要な強調位置の計算を省く。検索語変更・取消・終了でタイマーと走査用バッファを破棄する。別プロセスやスレッドは追加しない。

順不同のリテラルAND、大文字小文字を区別しない検索、除外ディレクトリ、隠しファイル、サイズ・結果数の上限、バイナリの除外、標準の文字コード判定を維持する。Consult/rgの検索仕様へ置き換えず、追加パッケージも不要とする。ファイル列挙と既存Consult連携は現在の経路を使う。

実リポジトリの検索時間・最初の結果・イベント処理の最大待ち時間を変更前後で記録する。大きいファイルと文字コードを変えた小さなテストでも、結果の一致・キャンセル・走査バッファの解放を検証する。物理キー入力や画面走査時間とは区別する。ファイル読取とディレクトリ列挙自体は同期処理のため、遅いドライブの待ち時間は残る。
